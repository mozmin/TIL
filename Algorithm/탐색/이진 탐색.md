# 이진 탐색
`정렬된` 데이터 내에서 탐색 범위를 절반씩 줄여나가며 원하는 값을 빠르게 찾아내는 탐색 알고리즘.

### 방법
1. 데이터의 정중앙을 찾는다.
2. 찾으려는 데이터가 정중앙의 값보다 앞에 있으면, 앞쪽 절반만 다시 탐색한다.
3. 만약 데이터가 정중앙의 값보다 뒤라면, 뒤쪽 절반만 다시 탐색한다.
4. 찾을 때까지 이 과정을 반복한다.

### 시간 복잡도
- `O(log N)`
- 데이터가 1,000,000 개일 때 완전탐색은 100만번, 이진탐색은 20만번 연산 가능

## 핵심 응용: 파라메트릭 서치 (Parametric Search)
코딩 테스트에서 이진탐색은 "정렬된 배열에서 값 찾기"보다, "조건을 만족하는 최적의 답 찾기" 형태로 훨씬 많이 나옴.

이를 `파라메트릭 서치` 라고 부름.

### 방법
1. 정답이 될 수 있는 값의 전체 범위(e.g., 0 ~ 10억)를 start와 end로 설정.

2. mid 값을 "임시 정답"이라고 가정.

3. mid 값이 문제의 조건(e.g., "모든 사람이 심사를 받을 수 있는가?")을 만족하는지 Yes/No로 판단. (이 판단 과정을 '결정 문제'라고 함.)

4. Yes (성공): mid값이 정답일 수 있지만, "최솟값"을 찾고 있으므로, 더 작은 값이 가능한지 탐색. (범위를 앞쪽 절반으로 줄임: end = mid - 1)

5. No (실패): mid값이 너무 작아서 조건을 만족하지 못했으므로, 더 큰 값이 필요. (범위를 뒤쪽 절반으로 늘림: start = mid + 1)


## 적용 문제: 프로그래머스 - 입국심사 (Level 3)
파라메트릭 서치를 적용하는 가장 대표적인 문제

### 문제 요약
n명의 사람이 입국심사를 기다리고 있음. 각 심사관마다 심사하는 데 걸리는 시간(times 배열)이 다름. 모든 사람이 심사를 마치는 데 걸리는 "최소 시간"을 구해야 함.

### 이진탐색(파라메트릭 서치) 적용
- **탐색 대상:** "배열"이 아니라 "시간" 그 자체를 탐색.

- **문제 변환:** "모든 사람이 심사를 마치는 최소 시간은?" $\rightarrow$ "$X$분이 주어지면, $n$명을 모두 심사할 수 있는가?" (Yes/No)

- **탐색 범위 설정:**
  - `start` (최소 시간): 0분 (또는 1분)
  - `end` (최악의 시간): `가장 오래 걸리는 심사관 시간` $\times$ `n명` (데이터 범위상 long 타입 필요)

- **mid값으로 판단하기:**
  - `mid`를 "주어진 시간"(임시 정답)이라고 가정. (예: mid = 30분)
  - A 심사관(7분)은 30분 동안 `30 / 7 = 4`명 처리
  - B 심사관(10분)은 30분 동안 `30 / 10 = 3`명 처리
  - `총 처리 인원 = (mid / 7) + (mid / 10)`
  - 이 `총 처리 인원`이 `n`명보다 많거나 같은지(Yes/No) 판단.

### Java 코드 구현
``` java
import java.util.Arrays;

class Solution {
    public long solution(int n, int[] times) {
        // [핵심] 이진탐색을 위해 '시간' 범위를 설정해야 합니다.
        // long 타입 사용에 주의! (최악의 경우 int 범위를 넘어섭니다)
        
        // 1. start: 최소 시간 (1초부터 시작)
        long start = 1; 
        
        // 2. end: 최악의 시간 (가장 오래 걸리는 심사관 * n명)
        //    효율을 위해 times를 정렬하면 end 값을 쉽게 찾을 수 있습니다.
        Arrays.sort(times);
        long end = (long) times[times.length - 1] * n;
        
        // 3. answer: '최소 시간'을 저장할 변수 (초기값은 최악의 시간)
        long answer = end;

        // 이진탐색(파라메트릭 서치) 시작
        while (start <= end) {
            // 4. mid: 우리가 "임시 정답"으로 가정한 시간
            long mid = (start + end) / 2;
            
            // 5. [결정 문제] "mid 시간 동안 몇 명을 심사할 수 있는가?"
            long totalPeople = 0;
            for (int time : times) {
                // 한 심사관이 mid 시간 동안 처리 가능한 사람 수
                totalPeople += mid / time; 
                
                // (최적화) 처리 인원이 n을 넘으면 더 계산할 필요 없이 break
                if (totalPeople >= n) {
                    break;
                }
            }

            // 6. 범위 조절
            if (totalPeople >= n) {
                // Yes (성공): n명 이상 처리 가능
                // -> "mid" 시간이 정답일 수 있음. 저장!
                // -> 하지만 "최소 시간"을 찾아야 하므로, 시간을 더 줄여본다. (앞쪽 절반 탐색)
                answer = mid;
                end = mid - 1;
            } else {
                // No (실패): n명을 처리하기에 시간이 부족함
                // -> 시간을 더 늘려야 한다. (뒤쪽 절반 탐색)
                start = mid + 1;
            }
        }
        
        return answer;
    }
}
```
