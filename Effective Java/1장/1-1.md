# 1-1. 생성자 대신 정적 팩토리 메소드를 고려하라

## 정적 팩토리 메소드
- new 생성자 호출 대신 클래스의 static 메서드로 인스턴스 반환하는 방식
- 형태: of(...), from(...), valueOf(...), getInstance(), create() 등 사용


```
// 생성자 호출 방식
new BigDecimal("1000.00");

// 정적 팩토리 방식
Money.of("1000.00");
Color.fromHex("#FF00AA");
```

### 장점
- 의도 표현 강화: 이름으로 생성 의미 드러내기
```
Range.closed(1, 10);   // 닫힌 구간 생성
Range.open(1, 10);     // 열린 구간 생성
```
- 재사용/캐싱 용이: 동일 값에 동일 객체 재사용, 메모리/GC 부담 감소
```
Integer.valueOf(42);    // 내부 캐시 활용
Boolean.valueOf(true);  // TRUE/FALSE 재사용
```
- 구현 은닉: 인터페이스 공개 + 하위 타입 선택/교체 캡슐화

- 검증/정규화 일원화: 파싱·유효성·정규화 로직을 팩토리에 모아 일관성 확보

- 오버로드 모호성 완화: 의미 있는 이름으로 가독성 향상

### 단점
- 발견성 저하: 생성자 대비 진입점 탐색 어려움 → 이름 관례·문서화로 보완
- 상속 제약: private 생성자 사용 시 상속 어려움 → 불변 값 객체에선 장점으로 활용
- 코드가 복잡해짐. 단순하고 직관성이 중요할 때는 기존 new 방식이 좋음

### 이름 관례
- of : 간단 변환/집계 사용 → Money.of("1000.00"), List.of(1,2,3)
- from : 단일 인자 변환 사용 → Color.fromHex("#FF00AA")
- valueOf : 의미 강조 사용 → Integer.valueOf(10)
- getInstance/instance : 캐시/조건부 동일 인스턴스 반환 사용
- newInstance/create : 항상 신규 인스턴스 생성 사용
- getType/newType : 다른 타입 반환 시 사용 → Files.newBufferedReader(...)

```
public interface PasswordEncoder {
    String encode(String raw);                 // 해시 생성 반환
    boolean matches(String raw, String encoded); // 검증 결과 반환

    // Java 8/11 호환 방식
    static PasswordEncoder of(String algo) {
        if ("bcrypt".equalsIgnoreCase(algo)) return new BcryptEncoder();
        if ("sha256".equalsIgnoreCase(algo)) return new Sha256Encoder();
        throw new IllegalArgumentException("Unsupported: " + algo);
    }
}

class BcryptEncoder implements PasswordEncoder {
    public String encode(String raw) { return "[BC]" + raw; }
    public boolean matches(String raw, String encoded) { return encoded.equals("[BC]" + raw); }
}

class Sha256Encoder implements PasswordEncoder {
    public String encode(String raw) { return "[SHA]" + raw; }
    public boolean matches(String raw, String encoded) { return encoded.equals("[SHA]" + raw); }
}

// 사용
PasswordEncoder enc = PasswordEncoder.of("bcrypt"); // 구현 선택 캡슐화
```
