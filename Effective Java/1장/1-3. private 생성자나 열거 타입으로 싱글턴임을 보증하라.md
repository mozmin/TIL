# 1-3. private 생성자나 열거 타입으로 싱글턴임을 보증하라

## 🧩 싱글턴(Singleton)이란?

> **클래스의 인스턴스를 오직 하나만 존재하게 하는 패턴**

예시:
- 로그(Log) 관리 객체
- 데이터베이스 연결 관리자(DB Connection Manager)
- 설정(Configuration) 객체

👉 이런 객체들은 **여러 개 만들면 안 됨**  
→ 데이터 일관성이나 자원 낭비 문제 발생

---

## 🧱 1️⃣ 고전적인 싱글턴 구현 (eager initialization)

```java
public class Elvis {
    public static final Elvis INSTANCE = new Elvis();

    private Elvis() {} // 외부에서 new 불가능

    public void sing() {
        System.out.println("🎵 Love me tender~");
    }
}
```

✅ 사용 예시
```
Elvis elvis = Elvis.INSTANCE;
elvis.sing();
```

### 💡 핵심
private 생성자로 외부 생성을 막고

클래스 내부에서 public static final 인스턴스를 하나만 만들어 제공

⚠️ 주의

멀티스레드 환경에서는 동기화 필요

동시에 여러 스레드가 호출하면 2개의 인스턴스가 생길 수도 있음

---

## 🧩 3️⃣ Enum으로 싱글턴 구현 (가장 완벽한 방법)

```java
public enum Elvis {
    INSTANCE;

    public void sing() {
        System.out.println("🎤 Can't help falling in love~");
    }
}
```

✅ 사용 예시
```
Elvis elvis = Elvis.INSTANCE;
elvis.sing();
```

💪 장점

JVM이 단 한 번만 로드 → 인스턴스 단 하나 보장

직렬화(Serialization)나 리플렉션 공격에도 안전

코드가 간결하고 명확

---

## 💬 왜 이렇게 해야 할까?
이유	설명
✅ 자원 절약	불필요한 객체 생성을 방지
✅ 일관성 유지	전역적으로 같은 상태를 공유
✅ 제어된 접근	통제된 접근점 제공 (getInstance 등)

---

## ⚠️ 주의할 점

싱글턴은 테스트가 어려움 (객체 교체 불가)

멀티스레드 환경에서는 초기화 시점 주의

“정말 하나만 필요한 객체인가?” 신중히 판단

---

## ✨ 정리 비교표
| 구현 방식                |	특징|	장점| 	단점     |
|----------------------|---|---|---------|
| public static final	 | 미리 생성 (eager)	| 단순, 빠름	리플렉션/직렬화 취약|
| getInstance()        |	필요 시 생성 (lazy)|	자원 절약| 	동기화 필요 |
| enum                 |	JVM이 1개만 보장|	가장 안전, 간결|	상속 불가|
