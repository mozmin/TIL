# 백엔드 개발자 필수 지식: 일급 컬렉션(First-Class Collection) 실무 활용법

백엔드 학습 시 접하는 '객체지향 생활 체조 원칙' 중 하나인 **"일급 컬렉션 사용"** 원칙. 단순한 리스트 래핑(Wrapping)으로 보일 수 있으나 실무 적용 시 코드 개선 효과가 큼. 일급 컬렉션의 개념과 현업(Java/Spring) 활용법 정리.

## 1. 일급 컬렉션 정의

**일급 컬렉션(First-Class Collection)**의 정의는 매우 단순.

> **Collection을 감싸면서(Wrapping), 그 외의 다른 멤버 변수가 없는 상태**

코드 예시.

```java
// 일반적인 사용 (Before)
Map<String, String> map = new HashMap<>();

// 일급 컬렉션 (After)
public class GameRanking {
    private Map<String, String> ranks;

    public GameRanking(Map<String, String> ranks) {
        this.ranks = ranks;
    }
}
```

단순 래핑으로 보이나 객체지향적 관점에서 중요한 이유 존재.

## 2. 사용 이유와 실무 코드 비교
쇼핑몰 '주문(Order)' 시스템 예시. 주문 시 여러 '상품(LineItem)' 포함.

**❌ Before: 일급 컬렉션 미사용**
서비스 레이어(Service Layer)에서 모든 로직 처리 시 발생하는 코드 형태.
```java
@Service
public class OrderService {

    public void createOrder(List<LineItem> items) {
        // 1. 비어있는지 체크
        if (items.isEmpty()) {
            throw new IllegalArgumentException("주문 항목은 필수입니다!");
        }

        // 2. 중복 상품 체크
        long distinctCount = items.stream()
                .map(LineItem::getName)
                .distinct()
                .count();
        if (distinctCount != items.size()) {
            throw new IllegalArgumentException("중복된 상품이 존재합니다!");
        }

        // 3. 총 금액 계산
        long totalAmount = items.stream()
                .mapToLong(LineItem::getPrice)
                .sum();
        
        // ... 주문 생성 로직 ...
    }
}
```
기존 코드의 문제점:

로직 분산: items 리스트 사용처마다 검증 로직 중복 발생 가능 (Controller, Service 등).

관리 어려움: List<LineItem>의 add, clear 등 무분별한 상태 변경으로 데이터 추적 난해.

불명확한 의미: List<LineItem> 변수명만으로는 역할 파악 어려움.

**✅ After: 일급 컬렉션 적용**
List<LineItem>을 감싸는 일급 컬렉션 OrderItems 구현.

```java
public class OrderItems {
    private final List<LineItem> items;

    public OrderItems(List<LineItem> items) {
        validateSize(items);
        validateDuplicate(items);
        this.items = items;
    }

    // 1. 검증 로직 캡슐화
    private void validateSize(List<LineItem> items) {
        if (items.isEmpty()) {
            throw new IllegalArgumentException("주문 항목은 필수입니다!");
        }
    }

    private void validateDuplicate(List<LineItem> items) {
        long distinctCount = items.stream()
                .map(LineItem::getName)
                .distinct()
                .count();
        if (distinctCount != items.size()) {
            throw new IllegalArgumentException("중복된 상품이 존재합니다!");
        }
    }

    // 2. 상태와 행위의 단일 관리 (계산 로직)
    public long calculateTotalAmount() {
        return items.stream()
                .mapToLong(LineItem::getPrice)
                .sum();
    }

    // 3. 불변성 보장 (읽기 전용 반환)
    public List<LineItem> getItems() {
        return Collections.unmodifiableList(items);
    }
}
```
개선된 서비스 레이어 코드.
```java
@Service
public class OrderService {

    public void createOrder(OrderItems orderItems) {
        // 검증 로직은 OrderItems 생성 시점 완료
        
        // 계산 로직 위임
        long totalAmount = orderItems.calculateTotalAmount();
        
        // ... 주문 생성 로직 ...
    }
}
```

**적용 효과:**

높은 응집도: 검증, 계산 로직이 OrderItems 내부에 위치하여 관리 용이.

데이터 안전성: Collections.unmodifiableList 사용으로 외부 변경 차단.

테스트 용이성: Service 없이 OrderItems 단위 테스트 가능.


## 3. 현업 활용 팁 (JPA 연동)
Spring Data JPA 사용 시 일급 컬렉션 매핑 방법.

💡 @Embeddable 활용
단순 값 모음이나 특정 엔티티 종속 컬렉션은 @Embeddable을 사용하여 필드로 매핑.

```java
@Embeddable
public class OrderItems {
    
    @OneToMany(cascade = CascadeType.ALL, orphanRemoval = true)
    @JoinColumn(name = "order_id")
    private List<LineItem> items = new ArrayList<>();

    protected OrderItems() {} // JPA 기본 생성자 필수

    public OrderItems(List<LineItem> items) {
        this.items = items;
    }

    // ... 비즈니스 로직 ...
}

@Entity
@Table(name = "orders")
public class Order {
    
    @Id @GeneratedValue
    private Long id;

    @Embedded // 일급 컬렉션을 필드로 선언
    private OrderItems orderItems;

    // ...
}
```

Order 엔티티의 컬렉션 관리 부담 감소 및 OrderItems로 로직 위임 가능.

## 4. 요약
일급 컬렉션은 **"상태와 행동을 한곳에서 관리"**하는 객체지향 원칙 준수 도구.

**활용 포인트:**

리스트/맵 사용 시 검증 로직(크기, 중복 등) 반복 발생 시.

컬렉션 데이터 기반 계산 로직(합계, 평균) 분산 시.

컬렉션의 불변성 보장 필요 시.

초기 클래스 생성 번거로움 존재하나 유지보수성 향상 효과 명확. 프로젝트 적용 권장.
