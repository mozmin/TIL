# 자바 정규표현식(Regex): 실무 효율화와 성능 최적화 가이드

백엔드 개발 시 입력값 검증, 로그 파싱, 마스킹 등 문자열 처리에 필수적인 **정규표현식**. 문법이 복잡해 보이지만 실무에서 사용하는 패턴과 최적화 방식은 정해져 있음. 자바(`java.util.regex`) 기반의 실무 활용법 정리.

## 1. 정규표현식의 핵심 클래스

자바 정규표현식 처리는 주로 `java.util.regex` 패키지의 두 클래스를 사용.

1. **Pattern**: 정규표현식 문자열을 컴파일하여 객체로 만듦 (비싼 작업).
2. **Matcher**: 패턴을 기반으로 실제 문자열과 매칭 작업을 수행.

## 2. 정규표현식 문법 기초 (Cheat Sheet)

실무에서 가장 자주 사용하는 핵심 문법 정리.

### 주요 메타 문자 (Meta Characters)

| 기호 | 설명 | 예시 |
| :--- | :--- | :--- |
| `^` | 문자열의 **시작** | `^A` (A로 시작하는 문자열) |
| `$` | 문자열의 **끝** | `z$` (z로 끝나는 문자열) |
| `.` | 줄바꿈을 제외한 **임의의 한 문자** | `a.c` (abc, aoc, a@c 등) |
| `\|` | **OR** 연산 (또는) | `a\|b` (a 또는 b) |
| `()` | **그룹핑** (하나의 묶음으로 처리) | `(abc)+` (abc가 반복됨) |
| `[]` | **문자 집합** (괄호 안의 문자 중 하나) | `[abc]` (a, b, c 중 하나) |
| `[^]` | **부정** (괄호 안의 문자를 제외) | `[^0-9]` (숫자가 아닌 것) |

### 수량자 (Quantifiers)

| 기호 | 설명 |
| :--- | :--- |
| `*` | 0개 이상 (없어도 됨) |
| `+` | **1개 이상** (필수) |
| `?` | 0개 또는 1개 (있을 수도 없을 수도) |
| `{n}` | 정확히 **n번** 반복 |
| `{n,m}` | **n번 이상, m번 이하** 반복 |

### 미리 정의된 문자 클래스 (Character Classes)

| 기호 | 설명 | 동등 표현 |
| :--- | :--- | :--- |
| `\d` | **숫자** (Digit) | `[0-9]` |
| `\D` | 숫자가 아닌 것 | `[^0-9]` |
| `\w` | **문자 + 숫자** (Word) | `[a-zA-Z0-9_]` |
| `\s` | **공백** (Space, Tab 등) | `[ \t\n\r]` |

## 3. 실무 활용 케이스 3가지

### CASE 1: 입력값 유효성 검증 (Validation)

회원가입 시 이메일, 전화번호, 비밀번호 복잡도 검사에 가장 많이 사용.

```java
// 전화번호 검증 예시 (010-xxxx-xxxx)
String regex = "^010-\\d{4}-\\d{4}$";
String input = "010-1234-5678";

boolean isMatch = Pattern.matches(regex, input); 
// 결과: true
```

> **⚠️ 주의할 점**
>
> `String.matches(regex)`나 `Pattern.matches(regex, input)`는 내부적으로 매번 **Pattern 객체를 생성(컴파일)**함.
> 트래픽이 많은 구간에서는 **성능 저하의 주범**. (아래 3번 항목에서 최적화 방법 설명)

### CASE 2: 민감 정보 마스킹 (Masking)

로그에 남기는 개인정보(전화번호, 카드번호 등) 가림 처리 시 `replaceAll`과 **그룹핑(`()`)** 활용.

```java
public String maskPhoneNumber(String phoneNumber) {
    // 그룹 1: 010, 011 등 식별번호
    // 그룹 2: 중간 3~4자리 (마스킹 대상)
    // 그룹 3: 마지막 4자리
    String regex = "(\\d{2,3})-(\\d{3,4})-(\\d{4})";
    
    // $1, $3은 유지하고 중간 그룹만 ****로 치환
    return phoneNumber.replaceAll(regex, "$1-****-$3");
}

// 실행: maskPhoneNumber("010-1234-5678") -> "010-****-5678"
```

### CASE 3: 문자열 파싱 및 추출 (Parsing)

비정형 로그 데이터나 특정 포맷의 문자열에서 원하는 값만 추출할 때 유용.

```java
String log = "[INFO] OrderID:ORD-9992 processed at 2023-10-01";
// "ORD-" 뒤에 오는 숫자만 추출하고 싶을 때
String regex = "OrderID:(ORD-\\d+)";

Pattern pattern = Pattern.compile(regex);
Matcher matcher = pattern.matcher(log);

if (matcher.find()) {
    String orderId = matcher.group(1); // 괄호로 묶은 첫 번째 그룹 추출
    System.out.println(orderId); // 출력: ORD-9992
}
```

## 4. 성능 최적화 (가장 중요)

실무 코드 리뷰에서 가장 많이 지적받는 부분. 정규표현식 컴파일(`Pattern.compile`)은 비용이 매우 큼. 메서드 호출 때마다 컴파일하지 말고 **static final 상수로 캐싱**하여 재사용 필수.

### ❌ Bad Case

```java
public boolean isEmailValid(String email) {
    // 호출될 때마다 Pattern 인스턴스 생성 -> GC 부하 증가, CPU 낭비
    return email.matches("^[A-Za-z0-9+_.-]+@(.+)$");
}
```

### ✅ Good Case

```java
public class ValidationUtils {
    // 클래스 로딩 시점에 딱 한 번만 컴파일 (재사용)
    private static final Pattern EMAIL_PATTERN = Pattern.compile("^[A-Za-z0-9+_.-]+@(.+)$");

    public static boolean isEmailValid(String email) {
        return EMAIL_PATTERN.matcher(email).matches();
    }
}
```

## 5. 자주 쓰는 실무 패턴 모음

복사해서 바로 쓸 수 있는 검증된 패턴들.

| 용도 | 정규표현식 (Regex) | 설명 |
| :--- | :--- | :--- |
| **숫자만** | `^[0-9]*$` | 숫자만 포함되었는지 확인 |
| **이메일** | `^[A-Za-z0-9+_.-]+@[A-Za-z0-9.-]+$` | 일반적인 이메일 형식 |
| **휴대폰** | `^01(?:0|1|[6-9])-(?:\d{3}|\d{4})-\d{4}$` | 010, 011 등 포함 하이픈 형식 |
| **비밀번호** | `^(?=.*[A-Za-z])(?=.*\d)(?=.*[$@$!%*#?&])[A-Za-z\d$@$!%*#?&]{8,}$` | 영문, 숫자, 특수문자 포함 8자 이상 (전방탐색 활용) |
| **한글만** | `^[가-힣]*$` | 자음/모음 제외 완전한 한글 문자열 |

## 6. 요약

1. **용도:** 유효성 검증, 마스킹, 데이터 추출에 강력함.
2. **주의:** `Pattern` 컴파일은 비싼 작업.
3. **최적화:** 반복 사용되는 정규식은 반드시 `static final Pattern`으로 선언하여 재사용.
4. **가독성:** 복잡한 정규식은 주석을 달거나 상수에 의미 있는 이름 부여 필요.

정규표현식은 '작성하는 것'보다 '검증된 것을 가져와서 최적화하여 사용하는 것'이 실무에서 더 중요.
